## Findings Fixed

1. **Production dependency gate:** October 15's existing audit rejected Next.js
   15.5.25 for [GHSA-4jqv-mc3x-m676](https://github.com/vercel/next.js/security/advisories/GHSA-4jqv-mc3x-m676)
   and [GHSA-mcj8-r9mp-w47p](https://github.com/vercel/next.js/security/advisories/GHSA-mcj8-r9mp-w47p).
   Upgrade Next.js and its matching lint configuration to 15.5.28; retain existing
   sharp/source-map fixes. Remove unrelated lockfile metadata churn. This fixes
   an observed audit blocker, not evidence of an exploited production system.
   The advisory's Pages Router/self-hosting conditions must not be represented
   as a demonstrated exploit against this App Router/Vercel application.
2. **Ambiguous contact attribution:** repeated `enquiry` values selected generic
   server-rendered copy but attributed the first value as commercial in the
   browser. Share the exact closed allowlist and reject repeated values for
   attribution too. Cover repeated identical/different values and unsafe input.
   No new personal data, events or tracking storage.
3. **In-flight draft loss:** only the send button was disabled while submitting.
   A user could edit fields during the request and then lose those unsent edits
   when success reset the form. Disable the fieldset while submitting, retaining
   the existing hydration protection. On a failed request, preserve the draft
   and consent, re-enable editing and permit an explicit retry. Browser coverage
   holds a mocked request open, checks disabled controls and retries after 503.
