## Listing Draft

**Title:** A technical integration review for your web-wallet swap journey

**Description:**

> Know what your wallet product needs before committing to a swap integration.
> I will assess one defined web-wallet journey for one identified product and
> deliver a written entry-to-return map, reuse/configuration/custom-work breakdown,
> dependency and evidence gaps, and an acceptance plan. You receive a reasoned
> recommendation: reuse an existing application, choose a provider widget, or
> scope custom engineering. The report is tailored to your actual interfaces and
> requirements, not a generic checklist or a commitment to buy my software.
>
> Includes one consolidated clarification round about the same journey. The
> fictional River Wallet sample shows the report format and separates source
> findings, mock demonstrations, assumptions and unverified customer tests.
>
> This is a technical assessment, not production implementation, a security
> certification, legal/regulatory advice, investment advice or a ready-to-run
> exchange. No new connectors, smart contracts, custody, real-money tests or
> guaranteed provider approval. Do not send wallet private keys, seed phrases,
> production credentials or personal customer data.

**One tier:** Integration review. One report, one product/journey, one clarification
round. No add-ons initially. **Suggested tags:** API Integration, Software
Architecture, Web Development, Blockchain, Technical Documentation, if available
and accurate in the chosen category. Do not stretch claims to match a category.

**Work steps:** map the supplied journey/interfaces; evaluate reuse and dependencies;
write recommendation and acceptance evidence plan; address the agreed clarification
round. Do not list purchase, submitting requirements or accepting delivery as work
steps; Upwork already handles those.

**Required customer inputs after purchase:** product/operator and target markets;
one journey with network/asset/recipient/return expectations; existing stack and
connector/interface documentation or an explicit statement that it is unavailable;
the engineering decision and constraints. Optional sanitized code excerpts require
permission to inspect. These are proposed Catalog requirements, not new site fields.

**Sample references:** attach a reviewed PDF export of `sample-assessment.md` and
the three screenshot files described in `demonstration.md` after gallery suitability
review. The full technical report is deliberately detailed; gallery images should
not be reduced into unreadable text. Remove outbound/contact links from any eventual
marketplace PDF export. No real company logos, testimonials or transaction claims.
Keep pre-contract discussion in Upwork; no direct-contact CTA in this listing.

**FAQ:**

- Will this deploy my swap app? No, deployment is a separately scoped project.
- Must I license your product? No; a widget or custom approach may be recommended.
- Can you guarantee all wallets/tokens or legal permission? No; required evidence
  and unsupported scope are part of the report.
- Can you review without my code? Yes, if the brief is specific enough; undocumented
  implementation details remain unverified instead of being assumed.
